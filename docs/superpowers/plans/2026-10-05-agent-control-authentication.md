# JAM-184 Agent Socket Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Require a fresh per-launch credential before any agent feed or control access, with automatic authenticated relay reconnects.

**Architecture:** Publish a private credential after binding the listener. Authenticate a bounded first NDJSON line before subscribing or dispatching controls. The relay reads the current credential for each attempt and exposes connected state only after acknowledgement.

**Tech Stack:** Existing Rust Tokio/serde/ring/zeroize/libc and Node fs/net APIs; Vitest, Rust integration tests and Playwright. No dependency changes.

**Spec:** [Approved design](../specs/2026-10-05-agent-control-authentication-design.md). James approved the revised spec, including BOTH feed and controls, directly in chat on 2026-10-05.

## Global Constraints

- Work only in `.worktrees/capture-agent-control-token` on its existing Linear branch. Preserve unrelated edits and other running services.
- Keep all current loopback binds, Webpack flags, TLS opt-in behavior and post-authentication control semantics. No HTTP caller authentication; that is JAM-196.
- Token: 32 random bytes, 64 lowercase hex characters plus LF in the file. Authentication/acknowledgement line: maximum 256 bytes INCLUDING LF, each with an absolute 5-second deadline.
- Immediate private parent: real directory, current UID, mode 0700. Credential: regular file, current UID, mode 0600, one hard link. Resolve ancestor aliases, reject immediate-parent/final-file symlinks. All Rust publication and cleanup operations use one validated parent FD; Node validates and reads one opened final-file FD.
- Bind first, publish second. Failed bind cannot rotate an existing token. Cleanup removes only the saved file identity. Ordinary Drop cleanup is covered; do not add signal handling or promise crash cleanup.
- Separate 16-pending and 64-authenticated connection permits. No subscriber, event, control or connected status before successful acknowledgement. No pre-auth control queue or bypass.
- Never log credentials, raw auth input, or put tokens in argv, UI state or SSE. Scope diagnostics to bounded server-side categories. This does not isolate same-UID programs or secure relay HTTP routes.
- TDD each deliverable, then a meaningful independent whole-branch code/security review. The invoked epic-task-cycle authorizes commits/publication after review gates; do not implement before plan approval.

## Review Focus

1. Credential replacement and path races: Task 1 tests unsafe files, validated-FD publication and replacement-safe cleanup.
2. Unauthenticated access or unbounded admission: Task 2 tests no feed/control effects, deadlines, both caps and service to existing sessions.
3. TCP fragmentation/coalescing: Tasks 2/3 test first-line limits and preserve larger trailing commands/events.
4. Stale attempts and credential rotation: Task 3 tests fresh reconnect reads, stop(), old socket callbacks and buffer/timer reset.
5. Test-only bypasses or overstated isolation: Task 4 authenticates real binary/browser paths and documents JAM-196's boundary.
